# AI ประกอบโครงสร้างกล่องด้วย "ภาษาแผง" (ระดับ 2) — ทดลอง

วันที่เริ่ม: 17 ตุลาคม 2026
สถานะ: **ต้นแบบใน local dev** — ตัวคอมไพล์/ตัวตรวจ + วงรอบ AI + หน้าทดลอง `tests/browser/structure.html`; ยังไม่ผูกกับ Project/cloud/billing
เจ้าของผลิตภัณฑ์ขอ (16 ต.ค. 2026): "ให้ AI สร้างกล่องได้จริง" — ไม่ใช่เลือกจากแคตตาล็อก

## แนวคิด

AI เดิมกรอกฟอร์ม (template + W/D/H) จากแคตตาล็อก; ระดับ 2 ให้ AI เขียน **พิมพ์เขียวเชิงโครงสร้าง** แทน — แผงอะไร ต่อกับแผงไหนที่ขอบไหน
ลึกเท่าไร มีลิ้นชนิดไหน — ส่วนเรขาคณิตที่ต้องผลิตได้จริง (ตำแหน่งบนแผ่นคลี่ ระยะเผื่อความหนา รูปร่างลิ้น ลำดับพับ ชั้นวัสดุ) เป็นหน้าที่ของคอมไพเลอร์
ฝั่งเรา แล้วตรวจด้วย fold engine จริง ถ้าผิดส่งรายการกลับให้ AI แก้ (สูงสุด 3 รอบ) — ผลจึง "ผลิตได้โดยโครงสร้าง" และยังเข้า 3D/blueprint/ไฟล์ส่งออกเดิมได้
เพราะได้ `Dieline` ชุดเดียวกับ template

## ภาษาแผง (สรุป — ฉบับเต็มใน `STRUCTURE_SYSTEM`)

- แผ่นคลี่ x ขวา y ลง มม.; ทุกแผงเป็นสี่เหลี่ยมผืนผ้า
- `panels[]`: แผงราก 1 แผง (`attach: null`, `w`/`h`) แผงอื่น `attach: { to, edge, fold: 90|180 }` + `size` (ระยะยื่นจากขอบ; ด้านขนานขอบยาวเท่าขอบแผงแม่)
- ขนาด: `"W" | "D" | "H" | "W/2" | "D/2" | "H/2"` = ขนาดด้านใน (คอมไพเลอร์บวก 2t ต่อแกน) หรือตัวเลข มม.
- `kind`: `body` ผนัง/ฐาน, `lid` ฝา (ลึก −t และหดข้างละ `tuckIn` อัตโนมัติ ยกเว้นมีปีก `side: "out"` ที่ขอบข้าง), `glue` ปีกทากาว (ขอบไกลเฉียง)
- `flaps[]`: `dust` (คางหมู ความลึกจากช่องเปิด), `tuck` (ลิ้นเสียบมุมมน เฉพาะบน `lid`, `tuck: true` ให้ fold engine ไถลเข้าผนัง), `tab` (สี่เหลี่ยมมุมเฉียง); `side: in|out` บอกว่าลิ้นแนบผนังจากด้านในหรือห่อนอก (แผ่นหนา 0 ตัดสินเองไม่ได้)
- `orientation`: `front` (ท่อตั้ง, tilt 0) / `base` (ฐานวางพื้น, tilt −90° เหมือน mailer/tray)

## คอมไพเลอร์ทำอะไร (ตามลำดับ)

1. วางแผงตามต้นไม้ (BFS จากราก) — hinge เรียงตามแบบ fold engine (แนวตั้ง บน→ล่าง, แนวนอน ซ้าย→ขวา) และเครื่องหมายมุมพับ "เข้าด้านใน" ต่อขอบ (top/right +, bottom/left −) ซึ่งพิสูจน์ด้วยการทำซ้ำ `generateTuckEndBox` ให้ตรงทุกแผง
2. วัดช่องเปิดในสภาพพับสุด (`rayExtent` จากขอบ ขยับเข้ากล่อง 0.5 มม. กันจุดชนตกบนขอบพอดี) → ตรวจฝาลึกเกิน/สั้นไป, ตั้งความลึกลิ้นกันฝุ่น (สูตรเดียวกับ template: `min(0.75·ขอบ, ช่อง/2 − inset − 2) − t`)
3. สร้างลิ้นจากคลัง (สูตรรูปร่างเดียวกับ template; ลิ้นบนฝาที่หดแล้วไม่หดซ้ำ)
4. ซ้อนทับ 2D → error
5. ชั้นวัสดุ: คู่ที่นอนแนบกัน (`findLandings`) → `zOffset = ±(t+0.05)` ทิศทางจาก `side` ของลิ้นเทียบ normal ของแผงที่ถูกแนบ
6. ลำดับพับ: เริ่มจาก body 0 / lid แม่+1 / ลิ้น แม่+1 แล้ว **จำลองพับจริง** (`checkFoldSweep`) — แผงที่ถูกกวาดทะลุถูกเลื่อนจังหวะให้ช้ากว่าตัวที่กวาด (พร้อมลูกหลาน) วนจนนิ่ง; กวาดทะลุแผงแม่ตัวเอง = ลิ้นยาวเกิน → error
7. ด้านที่ปิด (`coverageByFace`, นับเฉพาะ body/lid) → เตือนด้านที่ปิด < 85% (ถาด/ปลอกตั้งใจเปิด)
8. ประกอบ `Dieline`: เลื่อนให้มุมซ้ายบนเป็น 0,0, เส้นตัด/พับจาก `autoSegments`, ป้ายขนาด W/H/D

ผลที่ยืนยันแล้ว (`compile.test.ts`): ภาษาแผงทำซ้ำ `tuck-end` ได้ตรงทุกแผงทั้ง carton-300 และ corrugated-e (ต่าง < 0.6 มม. บน carton), ทำซ้ำ `sleeve`, และ
สำหรับกล่องไปรษณีย์/ถาดที่ไม่ได้บอกลำดับพับ คอมไพเลอร์เดาได้เองว่าผนังหน้า-หลังต้องรอลิ้นมุม (เหมือน template mailer stage 2) และปีกข้างฝา `side: out` ได้ชั้นวัสดุเป็นลบ

## วงรอบ AI (`designStructure`)

คำขอ (W×D×H + วัสดุ + prompt [+ โครงสร้างปัจจุบัน]) → AI ตอบ JSON (structured outputs ตาม `STRUCTURE_SCHEMA`) → `parseStructure` → `compileStructure` →
มี error → ส่ง `describeIssues(errors)` กลับเป็นข้อความผู้ใช้รอบถัดไป (บทสนทนาสะสม) → สูงสุด `MAX_ROUNDS` = 3; คืน `rounds[]` ให้ UI โชว์ว่า AI แก้อะไร
รุ่นตระกูล 5 ใช้ `effort: medium` (งานออกแบบคิดมากกว่าแปลงสเปก) + server-side fallback เหมือน box-spec; `max_tokens` 16000

## ข้อจำกัดของต้นแบบ

- แผงสี่เหลี่ยมเท่านั้น (ไม่มีหน้าจั่ว/โค้ง/หน้าต่าง/รูหิ้ว/ก้นล็อกอัตโนมัติ) — คลังลิ้นมี 3 ชนิด
- ตรวจการชนตอนพับเฉพาะคู่ที่ "นอนแนบกัน" (เหมือน foldOrder.test) + ฝาลึกเกินช่อง — ไม่มี mesh collision ทั่วไป
- ชั้นวัสดุซ้อนลึก > 2 ชั้นอาจ z-fight; ลิ้นที่แนบหลายแผงเลือกแผงเดียว
- ขอบที่ลูกใช้ต่อแผงแม่ไม่รับลิ้นเพิ่ม (กติกาข้อ 1) — กล่องที่ต้องการลิ้นสองฝั่งของบานพับเดียวทำไม่ได้
- endpoint เปิดเฉพาะ local dev (`isLegacyAiRouteEnabled`); ยังไม่มี credits/timeout ของ cloud (วงรอบ 3 รอบอาจเกิน 50 วินาทีของ Vercel — ต้องเป็นงานเบื้องหลัง)

## ขั้นถัดไป (ยังไม่ตัดสินใจ)
